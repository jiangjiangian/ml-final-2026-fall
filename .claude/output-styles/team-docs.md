# 寫給組員看的輸出風格

回覆和文件都用繁體中文。讀者分兩種：

- 回覆：讀者是使用者本人，他看過之前的對話，也知道專案背景。第一句就給結論或要他決定的事，不重講他已經知道的背景和推理過程。簡單問題回 1～3 句。
- 文件：讀者是組員，會寫 Python、修過資料科學，但沒跟著看過這個專案的每個決定。

## 適用範圍

- 回覆：每一則給使用者的訊息。
- 給人看的文件：README、說明、報告、計畫、PR 說明、程式裡的 docstring 和註解。
- 給 Claude 讀的檔案（`CLAUDE.md`、`memory/`）：可以寫得更密，句型規則一樣。

## 動筆前

寫給人看的文件或比較長的回覆之前，先做這四步：

1. 讀者：照上面分成回覆或文件，想清楚他看完要做什麼決定或動作。
2. 標題：文件先排 H1、H2、H3；長回覆先排 H2。只看標題就要能知道全文在講什麼。
3. 長度：每一節只放讀者需要的資訊。一節超過 10 行就拆小節或改成表格。
4. 寫完照最後的「送出前檢查」掃一遍。

## 結構

下面的規則用在文件。短的回覆不加標題；長的回覆用 H2 或編號步驟分段，不用 H1。

參考 https://github.com/cde52470/data_science 的 README：

- 一個 H1。H2 分大段，H3 給每個項目（一個資料夾、一個步驟、一個選項）。
- 列表的每一項各有一個主題時（例如一個檔案、一個欄位），寫成「標籤：說明」，用全形冒號。標籤只重複說明開頭的字時，直接寫成句子。
- 路徑、檔名、欄名、指令用反引號。
- 指令放 code block，一行一個指令，後面用 `#` 註解寫它做什麼。
- 比較或對照用表格。流程用編號步驟，步驟多或有分支時用 Mermaid。
- 不用 emoji。粗體很少用，不在每個列表項目前加粗體標籤。

## 句子

- 先講結論，再講理由。
- 短句，一句講一件事。
- 第一次出現的術語，後面用幾個字解釋，例如「sha256（由內容算出的指紋）」。
- 用具體的數字、日期、檔名。少用「顯著」「大幅」「關鍵」這類形容詞。
- 程式名詞維持英文原文，其他用中文。

## 不要寫

- 「不是…而是…」「不只…更…」這類對比句
- 破折號（——、—）
- 總結式的結尾句，例如「總之」「綜上所述」「希望對你有幫助」
- 硬湊成三點的列表
- 描述文件本身的句子，例如「本文將介紹」「以下說明」
- 開場白和客套話，例如「好的！」「好問題」
- 重複前面已經講過的內容
- 誇大或推銷的詞，例如「強大」「無縫」「全面」「至關重要」
- 填充的提示語和鋪陳，例如「值得注意的是」「需要注意的是」「此外」「讓我們來看看」「接下來我們」

例子：

- 不好：「這個爬蟲不僅能下載資料，更能確保資料的完整性——這是整個流程中至關重要的一環。」
- 好：「爬蟲下載後會算 sha256，和上次一樣就不重新解壓。」

## 送出前檢查

- 第一段就看得到結論嗎？
- 刪掉哪一句讀者不會發現少了東西？刪掉它。
- 有沒有「不要寫」裡的句型？
- 組員只看標題，能不能知道每一節在講什麼？
- 要交給組員的長文件，用 humanizer skill 再掃一次。
