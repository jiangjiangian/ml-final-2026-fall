# 比賽和課程網站

## 要做什麼

每個台股交易日的台北 09:00 前，預測 50 檔股票當天的 y，上傳 0/1 到 https://final.html2026.csie.org 。哪些日子是交易日，以 `/api/state` 的 `phase2Days` 為準，不用星期幾推算。

- 官方分數：0.000968。
- 模型：因果 TCN（只看過去資料的卷積網路），recipe `M3-2`，50 檔共用權重。目標是盤中報酬 ×100，輸出 > 0 判為 1。
- 特徵：15 個（7 個個股 lag、8 個市場特徵），其中 `tx_foreign_net_oi` 兩欄 100% 缺值，實際有資訊的是 13 個。

## 課程網站的 API

網址都寫在 `configs/config.yaml` 的 `course_site`，程式裡不要寫死。

| 用途 | 路徑 | 備註 |
|---|---|---|
| 登入 | `POST /api/auth/login` | JSON 帶 `email`、`password` |
| Training ZIP | `GET /downloads/fin_pred_data.zip` | ZIP 裡的路徑開頭多一層 `data/` |
| 當天範本 | `GET /api/sample-submission?phase=2&tradingDate={date}` | 用 `utf-8-sig` 讀，開頭可能有 BOM |
| Phase 1 範本 | `GET /api/sample-submission?phase=1` | 表頭 `id` 加 84 個交易日（2026-06-01～09-30） |
| 狀態 | `GET /api/state` | `phase2Days`、`openAt`、`deadline`、`uploadQuota`、`mySubmissions` |
| 上傳 | `POST /api/submissions` | JSON `{phase, tradingDate, fileName, payload, note}`，Phase 1 不帶 tradingDate；payload 見 `src/site_api.py` |
| 下載目前的提交 | `GET /api/submissions/{id}?record=current` | id 來自 `mySubmissions` |

`/api/state` 回傳的時間沒帶時區，當成 UTC。

## 上傳的規矩

- 截止：過了 t 當天台北 09:00 就不上傳。`submit.py` 自己用 08:50（`competition.upload_cutoff`），留時間核對。網站的截止更早時以網站為準。
- 順序照 `src/submit.py` 開頭：先查 `/api/state`（休市就結束，不算失敗；要在 `openAt` 和網站的 deadline 之間；`uploadQuota` 要有剩）。網站目前的有效提交和這份 CSV 一樣就不送。要送時，先在 `data/submission/upload_log.jsonl` 寫「準備上傳」，再 POST。
- 全新的雲端機器：這筆「準備上傳」要先 commit 並 push 成功才 POST，push 失敗就不上傳。不然下一次執行看不到紀錄，可能重送。
- POST 失敗或逾時：不自動重試。回去查網站有沒有收到。每天的上傳次數有上限。
- 核對：POST 拿到 200 也要把網站上的版本下載回來逐格比對，一致才算完成。
- 開關：`configs/config.yaml` 的 `submit.enabled` 是 `false` 時只印出要送的內容。改成 `true` 之前，要先跟使用者確認舊系統的排程已經停了（見 `memory/context/open-questions.md`）。

## 網站規則（2026-11-07 從網站前端的程式碼和 /api/state 查）

- 排行：Phase 1 從所有版本取最高分，同分時較早達成的優先；Phase 2 用各交易日的最新版本。所以多交 Phase 1 不會蓋掉最高分。
- 上傳次數：`uploadQuota.phase1` 是 `{day, userLimit, teamLimit, userCount, teamCount}`，`day` 是台北日期。每隊每天 10 次，`userLimit` 是 0，代表沒有個人上限。Phase 2 看 `phase2ByDate[t]`。
- `mySubmissions` 每個 phase（和交易日）只列目前有效的那份，舊的在 `submissionHistory`。`isAutoGenerated` 是 1 的是網站的「強制繳交」，不是我們交的。
- 目前 Phase 1 有效的那份：組員 2026-11-06 交的 `submission_holdout.csv`，0.002773（組員 `feature_switch.ipynb` 第 6 節的方法）。
- `phase2Days` 每天的 `enabled`（2026-11-07 從網站前端查）：管理員頁面每個交易日有「啟用／停用」按鈕；新建的交易日預設啟用。停用的日子不算進模擬競賽的排名（「已完整計分、未停用、且非競賽日」）。目前 18 天都是 1，沒看過 0。程式碰到 0 的處理見 `memory/context/pipeline.md`「休市」。
- 上傳時段（2026-11-07 改）：每個交易日從前一個交易日 09:01 開放，到當天 09:00 截止，所以隨時剛好開著一天。週一的時段跨週末（週五 09:01 到週一 09:00）。以前是前一天 15:00 開放。時間是管理員對每天設的 `openAt`、`deadline`，網站沒有寫成固定規則；學生只看得到現在落在時段內的那天。程式每次讀網站的值，不用改。
- 時段開著時，`/api/sample-submission?phase=2&tradingDate=t` 隨時拿得到範本（2026-11-07 週六拿到 11/09 的，50 檔，順序和 Phase 1 一樣）。
- `uploadQuota` 的 `day` 也跟著時段走：11/07 12:10 顯示 `2026-11-08`，看起來是 09:01 到隔天 09:00 算一天，用結束那天命名。
- 缺交：截止前沒交的組，答案匯入後網站強制繳交全 0，照常計分。
- 組員在時段內先手動交了 t 的版本，排程看到網站上已有就不送（`already_submitted`），不會蓋掉。
