# memory

專案的說明和紀錄。每個檔講一個主題，放在下面三個資料夾之一。哪個檔講什麼，看根目錄 `CLAUDE.md` 的「先讀哪個檔」那張表。

## 三個資料夾

### context/

專案本身的規則和環境：比賽規則、每天的流程、資料的規則、本機環境、還沒決定的事。之後每件工作都要照這些做。規則改了就直接改那一條，旁邊寫日期和誰決定的。

### projects/

每一條工作線的設計、進度和結果，例如爬蟲、特徵、一個 Kaggle 研究系列。一條線一個檔。自動研究（`/goal`、`/loop`）每一輪先讀的短檔叫狀態檔，和它的專案檔分開放，檔名用 `-state` 結尾，例如 `06-decider-research-state.md`。

### reference/

給組員查的說明，用組員看得懂的寫法：名詞、特徵表每一欄、每天交件的模型、排程主機。根目錄的 `README.md` 只放連到這裡的連結。

## 放哪個資料夾

| 問題 | 是的話放 |
|---|---|
| 這是之後每件事都要照著做的規則或環境嗎？ | `context/` |
| 這是一件有開始、有進度、會結束的工作嗎？ | `projects/` |
| 組員會來這裡查它嗎？ | `reference/` |

三個都像的時候，放最常被讀的那個，另外兩個地方只寫一行連結。同一件事只寫在一個檔。

## 檔名

- 格式：`NN-名字.md`。NN 是這個檔在這個資料夾裡建立的順序，兩位數，從 `01` 開始。
- 名字：小寫英文，字和字之間用 `-`。不用大寫、空白、底線。
- 新檔：用這個資料夾裡下一個沒用過的號碼。
- 刪掉的檔：號碼空著，其他檔不重新編號。重新編號要改所有引用，2026-11-16 這次整理改了 46 個檔、約 210 處。
- 搬到別的資料夾：在新的資料夾拿下一個號碼。
- 一個檔超過約 1,000 行：把已經結束的段落搬到新檔，檔名加 `-archive`（例如 `12-market-timing-archive.md`），原檔開頭寫一行連結。
- `README.md` 不編號。`memory/` 最上層只放這份 README，其他檔都要放進三個資料夾之一。

## 新增、搬動、刪除檔案時

1. 照上面的規則取名、放對資料夾。
2. 改 `CLAUDE.md`「先讀哪個檔」的表。
3. 搬動或刪除時，找出所有還寫著舊路徑的地方，一起改掉：

```bash
grep -rn "memory/舊的資料夾/舊的檔名.md" . --exclude-dir=.git --exclude-dir=.venv --exclude-dir=data   # 要找不到任何一行
```

4. `memory/reference/` 的檔有增減時，也改根目錄 `README.md` 的檔案樹。

## 寫法

- 使用者做了決定，寫進對應的檔，標上日期（例如 2026-11-16）。
- `context/03-open-questions.md` 的問題有答案後，搬到對應的檔，再從清單拿掉。
- 路徑都從 repo 根目錄算，例如 `memory/context/02-pipeline.md`。
