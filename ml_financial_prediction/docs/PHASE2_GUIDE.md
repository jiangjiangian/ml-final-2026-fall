## 用什麼排程？

目前建議用GitHub Actions或另一個能持久保存狀態的雲端執行器執行固定Python流程，Codex負責查問題、整理結果與協助修復。Codex／ChatGPT的部分介面有排程，但**本對話沒有建立排程的工具**；桌面本機專案通常需要電腦和app運行，網頁任務也不能假設繼承這個容器的資料與憑證。排程服務可能延遲，因此每階段仍檢查真實時間與09:00截止。

GitHub Actions的schedule只從default branch註冊，目前main為空；要實際啟用需安排合適入口、憑證、資料／模型／提交紀錄的持久儲存及失敗監測。單次手動rehearsal已成功，手動採集11來源成功、教師Training／Live及兩個FRED來源失敗並保留前版；這不等於所有資料已更新或定時job已啟用。具體設定與實測見[HOSTED_AUTOMATION](HOSTED_AUTOMATION.md)及[STATUS](STATUS.md)。

## 公開程式與組員資料

GitHub的所有branch共用repo可見性。若整個repo設Private，可以只邀請組員；若程式要Public而資料只供組員，須把原始資料與私有模型／提交狀態放另一個私人repo或私人object storage，讓公開程式透過受限憑證讀取。所謂私人data repo也是GitHub上的另一個repo，不需要自架資料庫。

目前同一私人repo的`live-data`包含教師資料。直接公開原repo會公開該branch及其資料；資料搬遷與原repo歷史處置完成前，不把它設公開。老師ZIP的公開再散布授權尚未核實，不假稱老師已禁止或已授權。程式已準備同repo私人儲存與分離私人資料repo的兩種路徑，最後選擇與實際權限仍需落實。
