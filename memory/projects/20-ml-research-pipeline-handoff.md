# 全新 ML 研究 pipeline 交接

## 研究目標

使用者 2026-11-23 要求重新檢查 ML 問題的起點，建立可持續循環的研究流程，從少量、可解釋的特徵和簡單模型開始，再用證據逐步增加複雜度，最後提出一個新架構和新模型。使用者特別關心大跌後能否辨識反彈，也不希望每天被固定成 25 檔猜漲、25 檔猜跌。

研究應從任務、標籤、評分和資料切分開始重查，不能先假定只是換一種模型。KDD Cup 的方法可作為研究線索，但必須查原始論文、競賽文件或作者程式，說明原任務和台股任務的差異。推薦系統、圖模型或深度模型不能只因為曾在比賽得獎就直接搬來。

目標是可重複的研究循環：

`資料與洩漏稽核 → 定義可否證問題 → 預先登記資料切分、基準、指標與門檻 → Kaggle smoke → Kaggle full → 獨立核對 → 記錄結論 → 登記下一個問題`

不要因單次黑天鵝行情承諾模型能預測未知事件。對大跌、急跌後反彈和一般日分開報告，也要說明每種情境的樣本數及不確定性。

## 本次檢查時的專案基準

- 比賽每天台北 09:00 前要預測 50 檔股票。`y = adj_close > adj_open`；官方分數依每檔盤中報酬 `r = adj_close / adj_open - 1` 計算，`score = mean((2 * pred - 1) * r)`。先讀 `../context/01-competition.md`。
- 正式交件模型是 `c2v2d`，備援為 `c2`、`rank_ensemble`、`persist`、`online_lr`。UB 研究設定的總目標是候選回測及影子跑都要勝過 `c2v2d`；新模型過關前不可擅自改正式設定。詳見 `13-unbound-count-model.md` 和 `../reference/05-daily-model.md`。
- 特徵文件記錄 110 欄，其中 55 欄列在 `model_columns`；這不表示正式模型會用完 55 欄。`rank_ensemble` 使用 41 個價量特徵，`c2v2d` 再用 20 個市場狀態和前 120 個有答案交易日估計的 β 排名。參考 `../reference/02-feature-table.md`、`../reference/05-daily-model.md` 和 `../../configs/config.yaml`。
- 特徵和標籤的時間定義、空值與資料來源規則在 `../context/05-data-rules.md`。不可用 t 當天開盤後才知道的價量、法人、指標或 `y`；驗證必須按日期切，不可隨機拆列。
- **N1 狀態需要先核對。** `13-unbound-count-model.md` 記錄 N1 於 11/23 部署到影子流程；本次對話檢視的 checkout 卻未在 `daily_model.shadow` 清單看到 N1，也未找到其模型檔。開始任何部署或把 N1 當作現行基準前，先核對分支、遠端和實際排程，不要把 memory 記載直接當作目前執行狀態。
- 本次任務沒有開始 Kaggle 新實驗，也沒有完成外部文獻查證。不得把研究計畫寫成已驗證的模型成果。

## 執行次序

### 1. 先確認問題與工具

讀取 `CLAUDE.md`、相關 `memory/context/`、`memory/reference/`，以及 KD 從頭設計的要求 `17-kdd-models-from-scratch.md`、反彈訊號研究 `18-rebound-signal.md` 和當天開盤前資料研究 `12-same-day-features.md`。檢查當前分支、工作樹和必要 Kaggle notebook 規則。確認可用的 Google 模型、Antigravity、skills、MCP、plugin 和 Kaggle 執行途徑；不要假設 OAuth 登入等於可使用 Kaggle，也不要索取或寫入密碼、token、cookie。

先清楚分開三個預測目標：

1. 個股盤中報酬的正負，即比賽標籤 `y`。
2. 個股盤中報酬的大小，即官方分數中實際被加權的 `r`。
3. 大盤處於急跌、一般或反彈等狀態，以及這些狀態在開盤前是否可辨識。

用事先定義、可從資料重算的規則定義「大跌」「反彈」和「反彈成功」，不可看完結果再挑日期或門檻。

### 2. 稽核資料與建立日期切分

逐欄確認資料的來源時間、可取得時間、標籤時間、缺失與修訂行為；從資料管線重建一份不含未來資訊的 point-in-time 樣本。以標籤日期分組切分，並檢查重疊視窗、標準化、特徵挑選、門檻選擇和模型重訓是否只使用當時可見資料。

先列出各來源實際涵蓋日期和品質，再預先登記 train、validation、test 的確切日期。不得直接把既有研究看過的 2006～2019、2022～2026 或 2025～2026 區段稱為全新未看過的測試集。保留一段凍結 holdout，只在候選與判讀規則凍結後使用一次；另外以逐日 walk-forward 模擬上線。正式比賽的未來日期可作為前瞻測試，不能拿來回頭調參。

### 3. 從基準與小特徵開始

預先登記並在同一批日期、同一個標籤上比較：

- 全猜 0、全猜 1、50/50 排名基準。
- `c2v2d`，作為目前正式系統的比較基準，不是新架構的設計模板。
- 一個不固定猜漲檔數的簡單統計基準。
- 正則化線性分類或報酬回歸等容易檢查的模型。

特徵由少至多分組加入，每次只加一組並保留消融：

1. 個股的過去收盤報酬、前一日盤中報酬、跳空與成交量。
2. 簡單的高低區間、波動和市場前一日報酬。
3. 開盤前已知的美股、台指期和波動訊號。
4. 只有在獨立日期區段證明有增益時，才考慮更多技術指標、產業、法人或交互作用。

每組都要比較增量、缺值率、跨時段穩定性和複雜度代價。不可一次塞入全表後以重要度排序，並將此稱為由簡至繁。

### 4. 逐層探索模型與可變檔數決策

先比較簡單分類和報酬預測，再依預先登記的結果決定是否嘗試樹模型、序列模型或新的架構。最後提出至少一個真正不同於現有選股集成／方向傾斜做法的新架構，清楚畫出輸入、輸出、訓練標籤、損失函數、推論和失敗備援；「新」指本專案新提案，不宣稱學術首創。

要直接檢驗取消固定 25/25 的決策方式。除分類機率外，評估預測條件期望報酬或與官方分數一致的目標；比較依凍結規則選擇 0～50 檔猜漲的決策層。記錄每天猜漲檔數、分數、方向準確率、報酬、換手或其他決策成本，以及不同大跌／反彈情境的表現。不可用測試答案選每天檔數、閾值或危機日期。

### 5. 嚴謹驗證與 Kaggle 執行

每一本 notebook 在執行前都要固定假設、資料版本／雜湊、日期切分、對照、候選數量、多重比較方法、評分方式、通過門檻和停止條件。對所有模型使用相同股票池、日期和答案；避免把同一日 50 檔當成 50 個獨立日期樣本。分數要按日做配對比較，並報告區間、每個時段與危機／反彈分層結果。

在 Kaggle 執行 smoke 後才跑 full；記錄 kernel 版本、輸入快照、套件版本、種子、耗時、輸出檔、錯誤和每個錨點。full 結果由另一個獨立檢查核對，至少重算重要數字、確認日期切分和資料未洩漏。若 Kaggle 連線、權限或 OAuth 不可用，明確回報阻塞點；可以準備 notebook 和精確執行步驟，但不能聲稱已執行。

候選達到事先登記的回測門檻後，才提議影子跑；影子跑只記錄、不上傳，需達成預定天數且每日重算一致。之後整理結果、限制、下一個假設到新編號的 `memory/projects/` 文件。正式 `daily_model.kind`、`fallback`、排程和資料管線的改動都須另取得使用者明確同意。
